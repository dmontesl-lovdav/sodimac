## STM-1403 — Filtro de seguridad por atributo de usuario (fiscal-api)

### Cambios
- **SecurityContextFilter** (nuevo): `OncePerRequestFilter` con `HIGHEST_PRECEDENCE`.
  Decodifica JWT (`sub`), consulta util-api, inyecta headers `x-user-vendors` /
  `x-user-types` / `x-user-groups` sobreescribiendo cualquier valor del cliente
  (anti-spoof).
- **UtilApiSecurityClient** (nuevo): cliente HTTP `java.net.http` con cache
  `ConcurrentHashMap` TTL 5 min. Usa propiedad `utils.api.url`.
- **JwtTokenInterceptor** (modificado): soporte `alg=none` vía
  `parseUnsecuredClaims()` cuando `fiscal.jwt.signing.publicKey` está vacío.
- **application-dev.properties** (modificado): `security.enabled=true`,
  `fiscal.jwt.signing.publicKey=` vacío para dev local.

### Pruebas
- Fernando (ATR001=11111): solo facturas de supplier 11111 ✓
- José (ATR001=11111,22222): facturas de ambos suppliers ✓
- Iván (ATR001=-1): todas las facturas ✓
- Ana (sin ATR001): HTTP 400 WRN7029 ✓
- Spoof (x-user-vendors=-1 + JWT Fernando): bloqueado, sigue filtrando 11111 ✓
- Complementos de pago: mismos escenarios validados ✓
