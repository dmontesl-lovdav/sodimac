Qué hace cada interfaz

SAPITO / FOSITO

enum: “SAPITO” · catálogo portal: “FOSITO” BD staging

Base de datos intermedia donde el portal registra y desglosa el documento antes de mandarlo a i213. El batch consulta la tabla Envios_Ap para saber si ya está registrado y si ya se envió.

SabemosBD SODIMAC_SAP, tabla Envios_Ap. Columnas CODIGO_PROVEEDOR, NUMERO_DOCUMENTO, NUMERO_UUID, FLAG_ENVIADO (0 = pendiente enviar, 1 = enviado, 2 = no enviado / error). SabemosAdapter SapitoRepositoryAdapter (batch invoice-status-sync). Por definirQué significa “SAPITO”; por qué el catálogo lo llama “FOSITO”; si son el mismo sistema (parece que sí).

DMS

comentario del enum de estatus Canal / transporte

Aparece solo como el mecanismo que mueve la factura de SAPITO hacia i213. El estatus 16 Error envío DMS = falló ese envío.

SabemosComentario en InvoiceStatus: “enviar la factura de SAPITO a i213 (DMS)”. Por definirQué es DMS (¿middleware? ¿bus? ¿siglas?), si es un sistema aparte o parte de i213, y quién lo opera.

i213

AdmIF213ProdDB @ 10.138.153.10:1433 AP contable + pago

Sistema de cuentas por pagar. Valida que el documento se contabilizó y que se pagó, vía stored procedures. El batch lee su resultado para avanzar el estatus en el portal.

SabemosSP i123_Valida_Documento_AP → contabilización (1 = ok, 0 = rechazo). Ojo: “i123” es typo del sistema origen. SabemosSP i213_Valida_Documento_Pagado_AP → pago (1 = pagado, devuelve REF_BANK). Por definirQué significa “i213”; su relación exacta con SAP PROD (¿i213 contabiliza en SAP o solo consulta?).

SAP (SODIMAC_SAP PROD)

ERP contable ERP

El ERP donde finalmente se contabiliza. Los estatus del portal hablan de “enviar a Sodimac SAP PROD” y “pendiente de contabilizar en SAP”.

SabemosAparece en descripciones de InvoiceStatus / CreditNoteStatus. La BD SODIMAC_SAP es la misma que usa SAPITO como staging. Por definirFrontera exacta SAP ↔ SAPITO ↔ i213 (staging vs. contabilización vs. AP). Aclarar con Ivan para no duplicar conceptos.
