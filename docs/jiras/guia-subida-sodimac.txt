 GUIA PARA SUBIR STM-704 Y STM-272 EN SODIMAC

================================================================================
 FIX ACTUAL: Archivos copiados en rama equivocada (STM-272 en vez de STM-704)
================================================================================

Problema: Los archivos AuditoriaApiService.java y AuditoriaApiServiceImpl.java
estan como "untracked" en la rama STM-272, y git no deja cambiar a STM-704.

Solucion paso a paso:

# 1. Guardar todos los archivos sin commitear (incluidos untracked)
git stash --include-untracked

# 2. Cambiar a la rama de STM-704
git checkout feature/STM-704-bitacora-auditoria-registro-facturas

# 3. Recuperar los archivos guardados
git stash pop

# 4. Agregar los archivos de STM-704 uno por uno
git add src/main/java/com/sodimac/fiscal/api/service/AuditoriaApiService.java
git add src/main/java/com/sodimac/fiscal/api/service/impl/AuditoriaApiServiceImpl.java
git add src/main/java/com/sodimac/fiscal/api/FiscalApiApplication.java
git add src/main/java/com/sodimac/fiscal/api/controller/InvoiceController.java
git add src/main/java/com/sodimac/fiscal/api/service/InvoiceService.java
git add src/main/java/com/sodimac/fiscal/api/service/impl/InvoiceServiceImpl.java
git add src/main/java/com/sodimac/fiscal/api/model/enums/AuditAction.java
git add src/main/resources/application-dev.properties

# 5. Verificar que estan staged
git status

# 6. Commit y push
git commit -m "feat(STM-704): integrar bitacora auditoria-api en registro de facturas y NC"
git push origin feature/STM-704-bitacora-auditoria-registro-facturas

# 7. Verificar que los archivos estan en el commit
git log --name-only -1

# 8. Verificar diferencias con develop
git diff develop --name-only


================================================================================
 PASOS PARA SUBIR STM-272 DESPUES DE MERGEAR STM-704
================================================================================

IMPORTANTE: NO crear PR de STM-272 hasta que STM-704 este mergeado en develop.
Si lo creas antes, el build fallara porque AuditoriaApiService no existe en develop.

# 1. Mergear STM-704 (facturacion) desde GitHub
#    - Ir al PR de STM-704 en GitHub
#    - Clic en "Merge pull request"

# 2. Actualizar develop en local (ya tiene STM-704 mergeado)
git checkout develop
git pull origin develop

# 3. Ir a la rama de STM-272 y traer los cambios de develop
git checkout feature/STM-272-bitacora-auditoria-complemento-pago
git merge develop

# 4. Si hay conflictos en AuditAction.java (ambas ramas lo modificaron):
#    - Abrir el archivo en el editor
#    - Resolver los conflictos (dejar todas las constantes REGISTRO_* + PAGO_*)
#    - Guardar y luego:
git add src/main/java/com/sodimac/fiscal/api/model/enums/AuditAction.java
git commit -m "merge develop into STM-272"

# 5. Verificar que compila
mvn clean package -DskipTests -q

# 6. Push y crear PR
git push origin feature/STM-272-bitacora-auditoria-complemento-pago
# Crear PR en GitHub → base: develop


================================================================================
 DIAGNOSTICO GENERAL: Si el build en cloud falla o git diff no muestra cambios
================================================================================

# 1. Confirmar en que rama estas
git branch

# 2. Ver si hay commits diferentes a develop
git log develop..HEAD --oneline

# 3. Si no hay commits, los archivos no se commitearon. Verificar:
git status

# 4. Si git status sale limpio y git diff develop --name-only sale vacio,
#    puede que copiaste los archivos ANTES de crear la rama
#    (los copiaste sobre develop y luego creaste la rama, quedando iguales).
#    Solucion: borrar la rama, volver a develop, crear rama, copiar archivos de nuevo:
git checkout develop
git branch -D feature/STM-704-bitacora-auditoria-registro-facturas
git checkout -b feature/STM-704-bitacora-auditoria-registro-facturas
# Ahora copiar los archivos modificados desde el workspace personal
# y repetir git add + git commit + git push
