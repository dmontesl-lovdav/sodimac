 PASO A PASO: PROYECTO 1 - fiscal-api
================================================================================

1. Clonar el repositorio de Sodimac (si no lo tienes):
   git clone https://github.com/sodimac/APP03022-mrch.backend.somx.fiscal-api.git
   cd APP03022-mrch.backend.somx.fiscal-api

2. Asegurarte de estar en develop y actualizado:
   git checkout develop
   git pull origin develop

3. Crear rama feature desde develop:
   git checkout -b feature/STM-272-bitacora-auditoria-complemento-pago

4. Copiar/aplicar los cambios de los 4 archivos listados arriba.

5. Verificar que compila:
   mvn clean package -DskipTests -q

6. Agregar archivos al staging:
   git add src/main/java/com/sodimac/fiscal/api/controller/PaymentRegistrationController.java
   git add src/main/java/com/sodimac/fiscal/api/service/PaymentRegistrationService.java
   git add src/main/java/com/sodimac/fiscal/api/service/impl/PaymentRegistrationServiceImpl.java
   git add src/main/java/com/sodimac/fiscal/api/model/enums/AuditAction.java

7. Crear commit:
   git commit -m "feat(STM-272): integrar bitacora auditoria-api en registro de complemento de pago

   - Agregar idTransaccion como query param obligatorio en POST /fiscal/complementos-pago/registrar
   - 13 puntos de auditoria en registerPayment() (request, validaciones, response)
   - 14 constantes PAGO_* en enum AuditAction
   - Inyectar AuditoriaApiService en PaymentRegistrationServiceImpl
   - Validacion FISCAL-ERR-102 si no se envia idTransaccion"

8. Push de la rama:
   git push origin feature/STM-272-bitacora-auditoria-complemento-pago

9. Crear Pull Request:
   - Base: develop
   - Compare: feature/STM-272-bitacora-auditoria-complemento-pago
   - Titulo: feat(STM-272): Integrar bitacora auditoria-api en complemento de pago
   - Descripcion:

     ## Resumen
     - Se integra el servicio auditoria-api para registrar trazabilidad en
       el flujo de registro de complementos de pago (registerPayment)
     - Nuevo parametro obligatorio: idTransaccion (query param)
     - 13 puntos de auditoria en flujo exitoso + 1 en error

     ## Archivos modificados
     - PaymentRegistrationController.java (idTransaccion + @Parameter)
     - PaymentRegistrationService.java (firma actualizada)
     - PaymentRegistrationServiceImpl.java (13 audit points + error)
     - AuditAction.java (14 constantes PAGO_*)

     ## Dependencia
     Requiere STM-704 mergeado primero (AuditoriaApiService + configs)

     ## Pruebas realizadas
     - Registro exitoso: 13 logs en auditoria
     - Sin idTransaccion: HTTP 400, FISCAL-ERR-102
     - Duplicado: 7 logs (6 OK + 1 error)

     ## JIRA
     STM-272
